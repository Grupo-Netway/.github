## Quem Somos

No **Grupo Netway**, conectamos tecnologia a operacao real, desenvolvendo solucoes digitais escalaveis para telecom e mercados de alta demanda.

### Missao

Conectar pessoas e organizacoes com solucoes digitais que **superam expectativas** e **eliminam barreiras**.

### Visao

Ser referencia em **engenharia de software, dados e automacao** no mercado de telecom e tecnologia.

### Valores

- Colaboracao radical e transparencia por padrao
- Responsabilidade com dados, seguranca e conformidade

- Autonomia com senso de dono

## Workflow de Desenvolvimento

```mermaid
flowchart LR
	A[Issue / Demanda] --> B[Branch feature/...]
	B --> C[Desenvolvimento + Testes locais]
	C --> D[Merge Request / Pull Request]
	D --> E[Code Review + CI/CD]
	E --> F[Merge em develop]
	F --> G[Release em main + Deploy]
```

1. Criar branch a partir de `develop`.

```bash
git checkout develop
git pull origin develop
git checkout -b feature/minha-feature
```

2. Fazer commits usando Conventional Commits.

```text
feat(api): adiciona endpoint de contratos
fix(ui): corrige layout do dashboard financeiro
chore(ci): ajusta pipeline de testes e lint
```

3. Abrir MR/PR para `develop`, incluindo sempre:

- Contexto da mudanca
- Prints/logs (quando aplicavel)
- Passos para teste manual

4. CI/CD executa automaticamente:

- Lint
- Testes
- Build

5. Aprovacao e merge:

- Aprovado -> merge em `develop`
- Releases partem de `main` com versionamento semantico

## Definition of Done (DoD)

Uma tarefa e considerada finalizada quando:

- Codigo implementado e revisado
- Testes locais executados com sucesso
- Lint sem erros
- Documentacao minima atualizada (README/changelog)
- PR/MR aprovado por pelo menos 1 reviewer
- Sem regressao funcional identificada

---

## Padroes de Codigo

- Linguagem padrao: TypeScript
- Commits: Conventional Commits
- Branches: `feature/*`, `fix/*`, `chore/*`, `hotfix/*`
- Estilo: ESLint + Prettier (onde aplicavel)
- Principios: Clean Code, SOLID, simplicidade e legibilidade
- Logs e erros: sempre com contexto e rastreabilidade

## Onboarding de Desenvolvedores

```bash
# 1) Clonar repositorio
git clone git@github.com:Grupo-Netway/<repo>.git
cd <repo>

# 2) Instalar dependencias
npm install

# 3) Configurar variaveis de ambiente
cp .env.example .env

# 4) Subir ambiente local
npm run dev

# 5) Rodar testes
npm test
```

Se algo quebrar nesse fluxo, abra uma issue ou acione o canal do time.

---

## Como Contribuir

1. Abra uma issue com contexto claro
2. Crie branch a partir de `develop`
3. Desenvolva com foco em qualidade e simplicidade
4. Garanta testes/lint/build locais
5. Abra PR/MR com descricao objetiva
6. Aguarde review e ajuste feedbacks
7. Merge apos aprovacao
